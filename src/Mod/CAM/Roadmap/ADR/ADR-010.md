# ADR-010: A tool holder is data on the tool bit

## Status
DRAFT

## Context

CAM needs to know what is above the cutting edges: the shank, and the **Tool Holder** the **Tool Bit** is set in. Uses of that knowledge include:

- a simulator drawing the **Tool Holder** and flagging (or, if asked, stopping) where it would hit the **Stock** or the **Workholding**, which at the machine is a crash;
- reach checks: how deep a tool can go before its holder hits the part;
- holder-aware toolpaths;
- the setup sheet's list of holders and stickouts.

At the machine, a tool holder goes in the spindle and grips the tool bit, either directly or through an adapter. It grips with a collet closed by a collet nut (an ER collet chuck, a router's collet nut), a heated bore that shrinks onto the shank (shrink fit), a set screw against the shank (an end mill holder), or jaws (a drill chuck). For collision checks only the outside matters: whatever grips the bit is inside the outline. Holders also come in long-reach and tapered (slim) versions, whose bodies reach well below the spindle nose.

This is about rotating tools in a spindle: milling, routing and drilling. CAM has no lathe or mill-turn support. A lathe's tool holders are different: a holder on the tool post or turret holds another holder, a boring bar or an insert holder, and neither is round about the tool's axis.

Options considered:

1. **A model file per tool holder.** Exact, but each check opens and recomputes a document.
2. **An outline as data:** (radius, height) points revolved about the **Tool Axis**. All a collision check needs; nothing is opened.
3. **Where it lives:** on the **Tool Controller**, or on the **Tool Bit**.
4. **The ISO 13399 tool assembly model:** the holder, any adapters and the cutting tool as separate items with standard properties and connection codes. It is made for tool management and inventory systems, and holds far more than a collision check needs.

## Decision

A **Tool Holder** file is a `.fcholder`, JSON holding the outline of everything from the face the bit comes out of (the exit face) up to the spindle nose, as (radius, height) points in millimeters, revolved about the **Tool Axis**: the exit face is at height 0 and heights run up toward the spindle. Each point is the largest radius at its height, so the outline is the holder's maximum extent; flats and wrench slots are covered, not drawn. The holder and whatever grips the bit in it (a collet and nut, a chuck, an adapter) are one outline; a shrink-fit holder's exit face is its tip. Long-reach and tapered holders are taller, narrower outlines; no extra fields are needed.

This covers spindle tool holders only. Lathe and mill-turn tool holders are left to their own ADR, if CAM gains that support.

"Tool holder" is the shop's term, and CAM keeps it. CAM is not a tool inventory, so it does not take up the ISO 13399 assembly model or its terms (option 4).

Built-in tool holders ship with CAM in `Tools/ToolHolder` (ER11 to ER50, ER8 to ER25 mini, router collet nuts); files in the user's CAM assets `Tools/ToolHolder` override them. The built-in files are collet-nut outlines only: a built-in ER32 covers the nut, not the holder body or taper above it. A holder body is covered only when a file draws it.

A file may also say what kind of holder it is (`type`, such as ISO30-ER32 or Shrink fit); CAM does not use it. An outline is drawn as a sketch: File > Open of a `.fcholder` builds the sketch on the XZ plane (X the radius, Z the height) and a VarSet of its name, type, notes and source; File > Export of the sketch writes a `.fcholder`, with arcs and curves as straight segments within 0.01 mm of them. A blank template is copied into the user's `Tools/ToolHolder`.

The **Tool Holder** (property `ToolHolder`) and the **Stickout** belong to the **Tool Bit**, not the **Tool Controller**: a bit is set in one holder at one stickout, measured from the exit face. They are set in the library, or on a **Job**'s copy of the **Tool Bit**. Stickout is not the gauge length a controller's tool length offset uses.

A **Job**'s **Tool Bit** carries a copy of its **Tool Holder**'s outline, so a document keeps its holders on any computer. A library **Tool Bit** file names its **Tool Holder** only; shared without the holder file, it has no tool holder on the other computer. A tool holder file that cannot be read also counts as no tool holder, with a warning. An edited holder file reaches a **Job** only through Update Tools from Library, like the rest of a tool's data. When a document opens, a **Job**'s **Tool Bit** that is set in a **Tool Holder** but has no copy of its outline (a **Job** saved before copies were kept), or whose copy no longer matches the holder file, is listed in the Update Tools from Library dialog. The copy changes only when that tool's update is accepted there. With that check turned off in the CAM preferences, the difference shows when Update Tools from Library is run.

## Consequences

- Gains: collision checks with no extra documents; tool holder sets shared as small files; one shape covers collet chucks, shrink-fit, set screw and drill chucks, adapters, long-reach and tapered holders.
- Costs: details such as flats are not drawn, as the outline is the maximum extent by design; built-in holders need body outlines added to check more than the nut.
